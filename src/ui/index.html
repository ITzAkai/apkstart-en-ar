Install Android to the virtual disk

The VM window is open. Follow these 6 steps once; after that ApkStart boots straight from the disk and no longer needs the image.

  1. Boot menu: press ↓ to select Installation - Install Android-x86 to harddisk, then press Enter
  2. Choose Partition: select Create/Modify partitions; when asked whether to use GPT, choose No
  3. Partition with cfdisk: New → Primary → press Enter to accept the size → Bootable → Write → type yes → Quit
  4. Format: select vda1 → when asked to format, choose ext4 → Yes
  5. Bootloader and system: Install GRUB → Yes; Install /system as read-write → Yes
  6. Done: when progress reaches 100%, click I've finished installing below (ApkStart restarts the VM and takes over)

If adb later says it isn't connected: in the VM window press Ctrl+Alt+F1 to open a terminal, run setprop service.adb.tcp.port 5555, stop adbd and start adbd, then press Ctrl+Alt+F7 to return to the graphical screen.

One system image is shared by the whole PC, and app data is kept in a differencing layer. Old images, old snapshots, logs and lock files can all be reclaimed. Logs roll over at a size limit and never grow without bound. Reset Android data really deletes several GB of user data and keeps only the system itself.
The diagnostic report helps with troubleshooting; rebuilding restores the desktop and Start menu entries
Stays in the tray after you sign in to Windows, so desktop icons open apps instantly without starting anything by hand.
App windows
Press F11 or right-click the tray icon to switch at any time. Full screen only enlarges the window: it keeps the aspect ratio and doesn't restart the app.
In window mode you can drag the edges to any size. This sets Android's internal render size; smaller is lighter on performance.
Mouse buttons
The emulator treats the left button as a finger tap; hold and drag to swipe. Nothing to set.
By default the emulator also treats right-click as a tap, which is easy to trigger by accident. When on, right-click only goes Back and no longer taps.
Smooth mode merges scrolling over a short interval into one swipe gesture. That avoids jerky step-by-step motion and doesn't start an adb process for every notch.
Side-button mapping needs a global mouse hook. The hook is installed only while an ApkStart app window is in the foreground and removed as soon as it loses focus or closes, so it never slows down the desktop.
These mappings apply only while an app window is in the foreground. On the desktop, or after the window closes, the mouse behaves exactly as usual in Windows.

Gives Android its own public DNS servers. By default Android uses the host's DNS, which can add hundreds of milliseconds per lookup when the host is on a VPN or a company network, so video apps load their first screen slowly. Turn this off if intranet domains stop working.
Lets app sounds and video audio play normally. Turn off only if you never need sound and want to save a little more CPU.

Container details (advanced)
Limits the vCPU quota and lowers process priority so the Windows desktop gets the CPU first. The Resource profile above already sets this for you.
Gaming mode keeps the Android VM at a higher CPU priority and reduces host-side polling for the lowest input and display latency, at the cost of slowing down other programs. When no app window is open, the container still drops to low priority automatically.
Also disables background packages such as the Play Store, setup wizard and print services, keeping only what apps need to run. If an app says Google Play services are missing, turning this off restores them automatically.
Boots the Android environment in the background as soon as ApkStart starts (its window stays hidden, so you never see the emulator). After that, opening any app is a single quick step: in testing, launch time dropped from over 20 seconds to almost nothing. The cost is about 1 GB of memory while idle; with this off, the first app launch is a cold boot.
Android boots once and stays running. Opening an app no longer restarts the whole system; it just starts that app and stops other app processes. Closing the last window clears background apps and parks the container, so the next launch is still instant.
